# ワイさんすう 仕様書

## 1. アプリケーション概要

- **アプリ名**: ワイさんすう（ysansu）
- **概要**: 計算ドリルのWebアプリ版。紙のドリルと同じレベル構成・合格基準を忠実に再現しつつ、問題をランダム生成することで何度でも繰り返し練習できる。
- **ターゲット**: 小学1年生〜3年生
- **コンセプト**: 紙のドリルの「位ごとに分解して暗算力を鍛える」段階的学習法をそのままデジタル化する。全問正解かつ制限時間内クリアで合格。

## 2. 原本PDF構成

原本: `計算ドリル　たし算.pdf`（44ページ）

- 11レベル構成（紙のドリルでは各レベル4枚の練習シートだが、Webアプリではレベル選択→毎回ランダム生成に置き換える）
- 合格基準: 全問正解 + ○タイム以内
- 二重丸(◎)基準: 全問正解 + ◎タイム以内

## 3. レベル定義

### 3.1. たし算レベル一覧

| レベル | 問題形式 | 問題数 | ○タイム | ◎タイム | 説明文 |
|--------|---------|--------|--------|--------|------|
| 1 | A + B = ? | 36 | 50秒 | 35秒 | つぎの けいさんを しなさい。 |
| 2 | A + B = ? | 36 | 1分30秒 | 1分 | つぎの けいさんを しなさい。 |

| 4 | A + B ⇒ 10の位 | 36 | 1分20秒 | 50秒 | つぎの けいさんの 10のくらいだけを たしなさい。 |

| 11 | A + B = ? | 36 | 3分30秒 | 2分20秒 | つぎの けいさんを しなさい。 |

### 3.2. 問題形式の分類

#### タイプA: 直接回答

```
A + B = [ ]
```

レベル1, 2, 7, 9, 11が該当。回答欄は1つ。

#### タイプB: 部分回答

```
A + B ⇒ [ ]（特定の位のみ）
```

レベル3（1の位のみ）、レベル4（10の位のみ）が該当。回答欄は1つ。

#### タイプC: 分解回答（3ステップ）

```
A + B = [ ] + [ ] = [ ]
```

レベル5, 6, 8, 10が該当。回答欄は3つ。

- 1つ目: 上位の位の合計（10の位 or 100の位+10の位）
- 2つ目: 残り（1の位の合計）
- 3つ目: 最終回答

### 3.3. 問題生成ルール

- 各オペランドの値域はレベル定義に従う
- 0のみの数は出題しない（各桁に0が含まれるのは許容。例: 30 + 52 は可）
- 直前と同一の問題は出題しない
- 問題数はレベル定義の通り（36問 or 18問）
- 毎回ランダムに生成する（固定問題リストは持たない）

### 3.4. オペランド値域の詳細

| レベル | 左辺 | 右辺 | 制約 |
|--------|------|------|------|
| 1 | 0〜9 | 0〜9 | 両方0は不可 |
| 2 | 10〜99 | 1〜9 | — |
| 3〜7 | 10〜99 | 10〜99 | — |
| 8〜9 | 100〜999 | 10〜99 | — |
| 10〜11 | 100〜999 | 100〜999 | — |

## 4. ゲームフロー

### 4.1. 画面遷移

```
ホーム → 演算種別選択 → レベル選択 → ドリル実行 → 結果表示
  │                                                    ↓
  │                                               レベル選択に戻る
  └→ 学習の記録（/history）
```

※ レベルを選択すると即座にランダム問題が生成されドリルが開始する。何度でも再挑戦可能。

### 4.2. ドリル実行フロー

1. カウントダウン（3, 2, 1, スタート！）
2. タイマー開始（バックグラウンド計測、画面には非表示）
3. 問題説明文を問題の上に表示
4. 問題を1問ずつ表示
5. ユーザーが回答を入力し、回答ボタンを押す
6. **小問ごとの正誤フィードバックは表示しない**（即座に次の問題へ進む）
7. **不正解でも次の問題へ進む**
8. **タイムアップ（○タイム超過）しても問題は続行する**
9. 全問終了後、結果画面へ遷移

### 4.3. 合格判定

| 判定 | 条件 |
|------|------|
| ◎合格 | 全問正解 AND 経過時間 ≤ ◎タイム |
| ○合格 | 全問正解 AND 経過時間 ≤ ○タイム |
| 不合格 | 上記以外（1問でも不正解、またはタイムオーバー） |

### 4.4. 結果画面の表示項目

- 合格判定（◎ / ○ / 不合格）
- 経過時間
- 正答数 / 全問数
- 全問正解時: 「🎉 ぜんもん せいかい！」
- 間違いあり時: 間違えた問題の一覧（正解付き）
- 「もういちど」ボタン（同じレベルで新しいランダム問題に再挑戦）
- 「レベルせんたく」ボタン

## 5. UI/UX設計方針

### 5.1. デザインコンセプト

任天堂マリオポータル（ https://www.nintendo.com/jp/character/mario/history/index.html ）を参考にしたデザイン。

- **配色**: 白ベースにアクセントカラー（赤・青）。子ども向けの親しみやすい色使い
- **レイアウト**: カード型UIでレベルを一覧表示
- **レスポンシブ**: タブレット/スマートフォン最優先（子どもの利用端末を想定）
- **フォント**: 大きく丸みのある読みやすいフォント
- **アニメーション**: カウントダウン演出、結果画面の判定バッジ演出

### 5.2. ドリル画面

- 問題説明文を問題の上に表示（レベル定義の description）
- 問題は画面中央に大きく表示
- タイプB（部分回答）は例題を常時表示
- タイプC（分解回答）は例題を常時表示
- 回答はテンキーUI（画面下部）
- テンキー: 0〜9、一文字削除（⌫アイコン）、回答ボタン（→アイコン）
- ボタンに文字は使わずアイコンのみ
- **タイマーは画面に表示しない**（バックグラウンドで計測し結果画面でのみ表示）
- 進捗バー（例: 15/36）を表示
- 入力は最大4桁に制限

### 5.3. レベル選択画面

- 演算種別ごとにレベルカードを表示
- 各カードにレベル番号、○タイム / ◎タイム、問題数を表示
- クリア状況（未挑戦 / △ / ○合格 / ◎合格）をアイコン表示
- ロック機構は設けない（どのレベルからでも選択可能）

### 5.4. 効果音

- **ドリル実行中の小問ごとの効果音は鳴らさない**
- カウントダウン: ティック音
- スタート: 開始音
- 結果画面: 判定に応じた効果音（◎ファンファーレ / ○合格音 / 不合格音）
- 効果音はWeb Audio APIでプログラマティック生成（音声ファイル不使用）
- 設定画面で効果音のON/OFF切り替え可能

## 6. データ永続化

### 6.1. 保存先

ブラウザの**LocalStorage**を使用する。サーバーサイドのデータベースは使用しない。

### 6.2. 保存データ

- **ユーザープロファイル**: ユーザー名、アバター（選択式）
- **クリア履歴**: 演算種別 × レベルごと x 実施時刻xタイムx(全問正解:○/不正解あり:×)
- **設定**: 効果音ON/OFF
- **最終プレイ**: 最後に選択した演算種別・レベル

### 6.3. 複数ユーザー対応

- 複数のユーザープロファイルを作成可能
- ユーザー切り替え機能をホーム画面に配置
- ユーザーごとにクリア履歴を分離

## 7. 拡張性設計

### 7.1. 演算種別の追加

初期リリースは「たし算」のみ。以下の演算種別を将来追加可能な設計とする。

| 演算種別 | ステータス |
|---------|----------|
| たし算（+） | v1.0で実装 |
| ひき算（−） | 将来対応 |
| かけ算（×） | 将来対応 |
| わり算（÷） | 将来対応 |

### 7.2. 設計方針

- 演算種別は設定ファイル（JSON/TypeScript定数）で定義する
- レベル定義（問題形式、オペランド値域、タイム、問題数）を演算種別ごとに独立したデータとして管理する
- 問題生成ロジックは演算種別ごとにStrategyパターンで実装する
- UIコンポーネントは演算種別に依存しない汎用設計とする

### 7.3. レベル定義のデータ構造（概念）

```typescript
const OPERATION_TYPES = ['addition', 'subtraction', 'multiplication', 'division'] as const;
type OperationType = (typeof OPERATION_TYPES)[number];
function isOperationType(value: unknown): value is OperationType;

type ProblemFormat = 'direct' | 'partial' | 'decomposed';

interface LevelDefinition {
  level: number;
  operation: OperationType;
  format: ProblemFormat;
  questionCount: number;
  timeLimit: {
    pass: number;      // ○タイム（秒）
    excellent: number;  // ◎タイム（秒）
  };
  operands: {
    left: { min: number; max: number };
    right: { min: number; max: number };
  };
  partialTarget?: 'ones' | 'tens';  // タイプBの場合
  description: string;
}
```

## 10. 非機能要件

### 10.1. パフォーマンス

- 初回読み込み: 3秒以内（Lighthouse Performance 90+）
- 問題切り替え: 体感遅延なし（100ms以内）
- テンキー入力: 即時反映

### 10.2. アクセシビリティ

- フォントサイズ: 最小16px、問題表示は24px以上
- タップターゲット: 最小44×44px（テンキーボタン）
- 色のみに依存しない情報伝達（正誤はアイコン併用）

### 10.3. ブラウザ対応

- Chrome（最新版）
- Safari（最新版、iPad Safari含む）
- 画面サイズ: 320px〜1200px

### 10.4. 運用

- デプロイ: Vercel（GitHub連携による自動デプロイ）
- 運用費: 無料枠内で運用
- サーバーサイド処理: なし（完全静的サイト）
